# Ишью: админка «Совет директоров» (7 экранов по макетам)

Готовые тексты для GitVerse. Макеты лежат в репозитории: `docs/aurora-mockups/s1…s7_*.html`
(открываются в браузере, размер 1280×800). Задачи — **только UI на моковых данных**,
без сети и бизнес-логики. Общие требования вынесены в конец файла — вставь их в каждое ишью
или оформи как общее закреплённое ишью/описание проекта.

---

## Ишью 1. Админка: экран «Подготовка заседания»

**Макет:** `docs/aurora-mockups/s1_meeting.html`

**Что сделать:**
- Верхняя навигация по шагам: «1. Заседание / 2. Планшеты / 3. Проведение / 4. Итоги»
  (активный шаг — оранжевый), справа бейдж «Подключено к серверу».
- Блок параметров заседания: название (текст), дата и время (текст), число участников.
- Блок «Вопросы повестки»: список из 5 моковых вопросов, у каждого — номер, формулировка,
  бейдж типа («За / против / воздержался» или «Выбор из списка»), бейдж правила
  («Простое большинство» / «2/3 голосов»), кнопка «Изменить» (пока без действия).
- Кнопка «Добавить вопрос» в заголовке (пока без действия или переход на заглушку).

**Критерии готовности:**
- Экран повторяет макет по структуре, цветам и отступам.
- Данные моковые, вынесены в отдельную модель/превью-данные.
- Сборка проходит, скриншот приложен к закрытию ишью.

## Ишью 2. Админка: редактор вопроса «За / против / воздержался»

**Макет:** `docs/aurora-mockups/s3_question_yna.html`

**Что сделать:**
- Заголовок «Вопрос N», кнопки «Отмена» и «Сохранить» (пока без действия).
- Левая колонка: поле «Формулировка вопроса», переключатель типа
  «За / против / воздержался» (выбран) / «Выбор из списка».
- Превью того, как участник увидит три кнопки: «За» (зелёная, ✓), «Против»
  (красная, ✕), «Воздержался» (серая, —). Подпись «Три варианта заданы
  автоматически и не редактируются».
- Правая колонка «Кворум и решение»: поле «Мин. кворум, участников» и
  радиокнопки «Простое большинство» / «Две трети голосов» / «Все “за”».

**Критерии готовности:**
- Соответствие макету; выбранный тип подсвечен зелёным.
- Состояние полей хранится в state (remember/ViewModel), моковые значения по макету.

## Ишью 5. Админка: экран «Проведение» — голосование открыто

**Макет:** `docs/aurora-mockups/s5_live.html`

**Что сделать:**
- Карточка текущего вопроса: «Вопрос 2 из 5 · За / против / воздержался» + формулировка.
- Блок состояния: статус «Голосование открыто» (зелёная точка), условия

**Критерии готовности:**
- Соответствие макету, оба типа результатов отображаются корректно.
- Счётчик «в протоколе 2 из 5» считается из мокового состояния.

## Общие требования ко всем 7 ишью (вставить в каждое)

- **Скоуп:** только UI + моковые данные. Сеть, ViewModel с логикой сервера,
  навигация между шагами — отдельные задачи потом.
- **Стиль строго по макету:** фон `#1B1B1D`, карточки `#2B2B2E` / `#38383C`,
  акцент оранжевый `#FF7A1A`, зелёный `#36C95F`, красный `#F0525A`,
  вторичный текст `#A9A9AE`; скругления 20–28 dp; шрифт Roboto.
  Цвета вынести в общий объект темы админки (по аналогии с `BoardColors`
  в `clients/tablet/feature/board`).
- **Размер макета:** 1280×800 (ландшафт, админка на планшете/десктопе).
- **Где делать:** новый модуль админки (предложение: `clients/admin` по аналогии
  с `clients/tablet`) — точное расположение согласовать с тимлидом до старта.
- **Ветка:** от `develop`, имя `admin/<номер>-<краткое-название>`,
  например `admin/1-meeting-prepare`.
- **DoD:** код компилируется (`:clients:admin:...:compileDebugKotlinAndroid`
  либо аналог для выбранного модуля), экран открывается и совпадает с макетом,
  скриншот приложен в ишью/PR.
